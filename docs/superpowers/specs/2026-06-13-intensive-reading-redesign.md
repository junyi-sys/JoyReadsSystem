# 精读计划重做 — 架构设计

**日期**: 2026-06-13
**状态**: 待确认
**问题**: 当前精读只有读后归纳一步，不是精读，是"读完说一句"。话题来源已经改成了好奇心种子，但阅读过程仍然太浅——每天一篇短文加一道归纳题，本质是泛读。

**精读 vs 泛读的关键区别**：
- 泛读：读完 → 知道大概 → 说一句
- 精读：带着一个主问题读 → 拆成几个小问题逐个搞懂 → 拼回来自己讲出答案

---

## 一、现状 vs 目标

| 维度 | 现状 | 目标 |
|------|------|------|
| 主线 | 无，读完随意归纳 | 一个主问题贯穿始终，读完能自己回答 |
| 读前 | 一段固定引导文字 | 抛出主问题 + 背景知识，激发"我想知道答案" |
| 读中 | 无交互 | 分段阅读，每段1题，为回答主问题积累线索 |
| 读后 | 1道口头归纳题 | 2-3道小问题（找线索→推因果→联系自己），最后回到主问题 |
| 拓展 | 无 | 主问题延伸：孩子用自己的话讲给大人听 |
| 整体 | 4步其中3步是走过场 | 主问题 → 子问题链 → 回到主问题，一个完整的探究闭环 |

---

## 二、核心设计：主问题 + 子问题链

```
                     ┌──────────────────┐
                     │    主问题         │
                     │ 这篇文章要搞懂什么  │
                     └────────┬─────────┘
                              │
              ┌───────────────┼───────────────┐
              │               │               │
         ┌────▼────┐    ┌────▼────┐    ┌────▼────┐
         │ 小问题1  │    │ 小问题2  │    │ 小问题3  │
         │ 找线索   │ →  │ 推因果   │ →  │ 联生活   │
         │ 文中定位 │    │ 理解机制 │    │ 迁移运用 │
         └────┬────┘    └────┬────┘    └────┬────┘
              │               │               │
              └───────────────┼───────────────┘
                              │
                     ┌────────▼────────┐
                     │   回到主问题     │
                     │ 孩子用自己的话讲  │
                     └─────────────────┘
```

三个小问题各有明确作用：

| 问题类型 | 作用 | 示例 |
|----------|------|------|
| 找线索 | 在文中定位关键信息，训练信息提取 | "蚂蚁的腿和身体有什么特别的地方？" |
| 推因果 | 把线索串起来，理解为什么会这样 | "这些特别的结构怎么帮助它搬重物？" |
| 联生活 | 把文章和孩子的经验连起来，加深理解 | "你有没有见过小个子大力气的事情？" |

## 三、核心流程（四阶段）

```
┌──────────────────────────────────────────────────────────────┐
│ 阶段1：读前热身 — 抛出主问题                                  │
│  ￭ 背景小知识（AI生成2-3句，关联孩子生活）                    │
│  ￭ 🎯 主问题展示（今天要搞懂什么）                            │
│  ￭ "这个问题的答案就藏在今天的文章里，读完你来告诉我！"        │
│  ￭ 孩子点"我准备好了!"进入                                   │
├──────────────────────────────────────────────────────────────┤
│ 阶段2：读中探究 — 分段阅读，积累线索                           │
│  ￭ 文章分3段展示                                              │
│  ￭ 每段读完 → 提示"这段有解决主问题的线索"                     │
│  ￭ 找线索题（从这段你发现了什么？）                            │
│  ￭ 孩子语音回答 → 轻反馈 → 下一段                              │
│  ￭ 进度条：段落 2/3，线索 1/3                                  │
├──────────────────────────────────────────────────────────────┤
│ 阶段3：读后思考 — 子问题链逐题击破                              │
│  ￭ 子问题1（找线索）：文中找到的关键信息是什么？                │
│  ￭ 子问题2（推因果）：为什么会这样？                           │
│  ￭ 子问题3（联生活）：你有没有见过类似的事？                    │
│  ￭ 每题AI即时判断 + 鼓励反馈                                   │
├──────────────────────────────────────────────────────────────┤
│ 阶段4：回到主问题 + 拓展                                       │
│  ￭ 🎯 回到主问题："现在你能回答了吗？"                         │
│  ￭ 孩子用自己的话回答 → 录音 → 转文字 → 保存                   │
│  ￭ AI给最终反馈（对比孩子最初的猜想和现在的答案）               │
│  ￭ 完成动画 + 今日阅读记录                                     │
└──────────────────────────────────────────────────────────────┘
```

## 四、LLM 一次生成完整教案

`start_day` 调用 LLM 时，prompt 要求返回结构化 JSON，一次生成全部内容。核心变化：**主问题引导整份教案，子问题各有明确的认知作用**。

```json
{
  "main_question": "蚂蚁为什么能搬动比自己重的东西？",
  "pre_reading": {
    "background": "你知道吗？蚂蚁是自然界的大力士！一只小蚂蚁能搬动比自己重50倍的东西。",
    "hook": "蚂蚁为什么能搬动比自己重的东西？这个问题的答案就藏在今天的文章里，读完你来告诉我！"
  },
  "paragraphs": [
    {
      "text": "那天你在院子里看蚂蚁，突然问：蚂蚁那么小，怎么能搬动比自己重好多倍的东西呢？...",
      "clue_prompt": "这段里，蚂蚁的身体有什么特别的地方？找出来告诉爸爸！",
      "clue_hint": "腿的结构、身体大小"
    },
    {
      "text": "其实蚂蚁的秘密藏在它的肌肉和骨骼里...",
      "clue_prompt": "这段告诉我们蚂蚁的力气从哪里来？",
      "clue_hint": "肌肉排列方式、外骨骼"
    },
    {
      "text": "蚂蚁不只是自己搬，还学会了合作...",
      "clue_prompt": "除了身体结构，蚂蚁还有什么办法搬重物？",
      "clue_hint": "合作、团队力量"
    }
  ],
  "sub_questions": [
    {
      "type": "find_clue",
      "label": "找线索",
      "question": "蚂蚁的腿和身体有什么特别的地方？",
      "answer_hint": "腿上有小钩子、外骨骼支撑、肌肉排列紧密"
    },
    {
      "type": "infer_cause",
      "label": "推因果",
      "question": "这些特别的结构怎么让它变成大力士的？",
      "answer_hint": "小钩子抓住地面不滑，外骨骼像盔甲支撑身体，肌肉力量集中"
    },
    {
      "type": "connect_life",
      "label": "联生活",
      "question": "你有没有遇到过看上去很小但力气很大的事情？",
      "answer_hint": "比如小磁铁吸起大铁块、小水泵抽很多水"
    }
  ],
  "extension": {
    "back_to_main": "现在你能告诉爸爸，蚂蚁为什么能搬动比自己重的东西吗？用你自己的话说！",
    "ai_feedback_hint": "从身体结构（腿/外骨骼/肌肉）和团队合作两个角度评价孩子的回答"
  }
}
```

**容错**: JSON 解析失败 → 回退到旧模式（只显示文章+一道归纳题）

## 五、后端改动

### 5.1 `plan/service.py` — `start_day`

- 改：LLM prompt 改为要求返回 JSON 格式完整教案（含 `main_question` + `sub_questions[]`）
- 改：解析 JSON → 存入 `PlanDay.guide_text`（JSON字段）
- 改：返回结构新增 `lesson_json` 字段（前端直接使用）

### 5.2 `plan/service.py` — `complete_day`

- 改：接受多道题答案数组 `answers: [{question_type, question, child_answer}]`
- 改：子问题3道 + 主问题1道 = 4条 `ComprehensionRecord`
- 改：阶段4主问题回答录音自动保存为 Theory

### 5.3 `plan/router.py`

- 改：`POST /api/plan/days/{id}/complete` body 改为数组

## 七、数据流

```
PlanPage → 点击某天
  → ReadingSessionPage mount → planApi.startDay(dayId)
  → 后端 start_day:
      1. LLM.generate(教案prompt) → JSON
      2. 解析JSON → guide_text存JSON
      3. 用paragraphs拼接article → 创建DailyArticle
      4. 返回 {article_id, lesson_json}
  → 前端渲染4阶段，主问题固顶
  → 每阶段答案暂存本地state
  → 阶段3完成 → planApi.completeDay(dayId, {answers: [
       {question_type: "find_clue", question: "...", child_answer: "..."},
       {question_type: "infer_cause", question: "...", child_answer: "..."},
       {question_type: "connect_life", question: "...", child_answer: "..."},
       {question_type: "main_question", question: "...", child_answer: "..."},
     ]})
  → 后端 complete_day:
      1. 子问题3道 + 主问题1道共4条 ComprehensionRecord
      2. 主问题回答录音 → 创建Theory
      3. 触发概念提取(已有)
      4. 返回 {ok: true, feedback: "..."}
  → 庆祝 → 返回PlanPage
```

## 九、风险与回退

- LLM JSON 不稳定 → 加 `json` validation，解析失败回退旧模式
- 子问题质量 → 三种类型在 prompt 中有明确示例，降低随机性
- 耗时较长 → start_day 已经异步，前端 loading 状态足够
- 后续迭代 → 可加 TTS 朗读文章、朗读评测、写字练习
